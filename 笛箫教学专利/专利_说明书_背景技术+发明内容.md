# 一种基于叙·框·境·创四维框架的笛箫民乐交互式教学系统及方法

## 技术领域

本发明属于智能音乐教育技术领域，具体涉及一种基于叙·框·境·创（Narrative-Framework-Scenario-Creation, NFSC）四维教学框架的笛箫民乐交互式教学系统及方法，适用于竹笛、洞箫等吹管乐器的智能化教学与训练评估。

---

## 背景技术

笛箫作为中国传统吹管乐器的代表，其教学长期以来以"师徒制"和"口传心授"为主要模式。这一传统模式在数字化时代面临四重结构性缺陷，每重缺陷均可量化为具体的技术参数差距。

**第一，技术诊断缺乏量化手段。** 在传统教学中，教师对学生演奏的评估完全依赖主观听觉。例如：教师听到学生吹奏的"La"音（标准频率440Hz），只能凭经验判断"偏高了一点"或"偏低了一点"——教师无法说出"偏高约12音分（实际频率约443Hz）"。这种主观评估方式使得学生无法获得精确的偏差数值、无法追踪每日的进步曲线、也无法量化比较不同练习方法的有效性。对于成人零基础学习者（45岁以上），听觉敏感度已下降约10-15dB，对自身演奏偏差的感知能力仅为儿童学习者的30%-40%，更加依赖外部量化反馈。

**第二，练习场景与演出场景之间存在不可控的差距。** 学习者在安静的琴房（背景噪音约20-30dB）中能够流畅完成的曲目，在面对真实观众（背景噪音约50-70dB、视觉干扰、心理压力）时，错误率平均上升40%-60%。传统教学无法在安全的练习环境中模拟演出压力的各项物理参数（噪音分贝值、合奏声部延迟毫秒数、视觉灯光变化），导致学习者必须通过真实的"失败演出"来积累经验——这一过程效率极低且对学习信心有显著负面影响。

**第三，即兴创作能力缺乏结构化、可量化的评估工具。** 传统教学中，教师对即兴演奏的评价只有"好听"或"不好听"两种结果，无法将"好听"分解为可量化的子维度——如"学习者即兴段落的风格与江南丝竹风格的匹配度是多少"、"即兴段落的旋律新颖度占比是多少"、"与50个预设风格模板中最接近的是哪一个"。这使得即兴能力的培养路径不清晰，学习者不知道自己的"创作短板"在哪里。

**第四，成人学习者的学习动机衰减曲线陡峭。** 数据表明：12岁以下儿童笛箫学习者的6个月留存率约为70%，而45岁以上成人学习者的6个月留存率仅为25%-30%。成人学习者的"首次放弃高峰"出现在第3-4周——即枯燥的持笛姿势和口风练习阶段。这表明成人学习者需要一种不同于"每日练功"纪律驱动的教学入口——一种与情感记忆和意义感知紧密关联的叙事驱动入口。

**现有技术方案的适配性缺失。** 目前已有的智能音乐教学系统（Simply Piano、Yousician、Flowkey等）均面向钢琴或吉他类乐器设计，其底层技术假设为"音高与物理键位/品位存在一一对应关系"和"演奏评估可简化为正确按键的二值判断"。笛箫的音高取决于口风角度、气息压力、指法组合三变量的连续协同——同一个"La"音（440Hz），可以通过"口风收紧+气息减弱+指法全按"或"口风放松+气息增强+指法半按"两种完全不同的组合方式吹出，不存在逐个键位的离散映射。因此，现有技术方案无法直接适配笛箫教学。

# 第一模块：装配叙事情境模块（叙模块）

## 模块定位

叙模块是整个系统的入口。它的工作是在学习者开始演奏之前，将一个"练习任务"转变为"一个需要被演绎的故事"。其技术本质是一个多媒体数据播放器——它读取一个 JSON 配置文件，在浏览器中渲染一张包含文本、音频和标记的叙事卡片。

## 零件清单（本模块专用）

| 编号 | 零件 | 类型 | 说明 |
|------|------|------|------|
| N-01 | narrativeData | JavaScript 对象 | 从 narrative_library.json 解析得到的完整叙事数据 |
| N-02 | trackCardTemplate | HTML 字符串 | 曲目选择卡片的 DOM 模板 |
| N-03 | narrativeOverlay | HTMLDivElement | 叙事蒙层的 DOM 容器 |
| N-04 | bgAudioPlayer | HTMLAudioElement | 背景音频播放器 |
| N-05 | expressionMarkLayer | HTMLDivElement | 演奏表情标记的叠加显示区域 |

## 装配步骤

### 步骤 S1：加载叙事情境数据文件

**S1.1** 当浏览器加载教学系统首页时，在 `<script>` 标签内执行以下初始化代码：

```javascript
// 步骤 S1.1：声明全局变量，用于存储叙事数据
let narrativeData = null;           // 将存放从 JSON 文件解析出的完整叙事数据
const NARRATIVE_JSON_URL = './data/narrative_library.json';  // JSON 文件路径

// 步骤 S1.2：发起 HTTP GET 请求，从服务器获取叙事数据文件
async function loadNarrativeData() {
    try {
        // S1.2.1：使用浏览器的 fetch API 发起网络请求
        let response = await fetch(NARRATIVE_JSON_URL);
        // S1.2.2：检查 HTTP 响应状态码。200-299 表示成功
        if (!response.ok) {
            // S1.2.2.1 分支：HTTP 状态码异常（如 404 文件不存在、500 服务器错误）
            console.error('叙事数据文件加载失败，HTTP状态码：' + response.status);
            throw new Error('HTTP_' + response.status);
        }
        // S1.2.3：将响应体（JSON 字符串）解析为 JavaScript 对象
        narrativeData = await response.json();
        console.log('叙事数据加载成功，共 ' + narrativeData.tracks.length + ' 首曲目');
    } catch (error) {
        // S1.2.4 分支：网络请求或 JSON 解析失败
        console.error('叙事数据加载异常：' + error.message);
        // S1.2.5：回退策略——使用内置的 3 首默认曲目数据，确保系统仍可基本运行
        narrativeData = getDefaultNarrativeData();  // 调用内置默认数据生成函数
    }
}
```

**S1.3** 解释 `fetch()` 的行为：该函数发起一个异步 HTTP GET 请求（默认方法=GET），返回值是一个 Promise 对象。当网络正常时，Promise 会解析（resolve）为一个 Response 对象；当网络断开、DNS 解析失败或服务器无响应时，Promise 会拒绝（reject），进入 `catch` 分支。

**S1.4** 如果进入 `catch` 分支——即网络断开或 JSON 文件不存在——系统调用 `getDefaultNarrativeData()` 函数：

```javascript
function getDefaultNarrativeData() {
    // 返回一个硬编码的最小叙事数据集（3首曲目）
    return {
        "version": "1.0",
        "fallback": true,  // 标记此数据为回退版本
        "tracks": [
            {
                "id": "DZ_DEFAULT_001",
                "title": "沧海一声笑（内置）",
                "level": "入门",
                "narrativeType": "叙",
                "tags": ["江湖", "侠客豪情", "洒脱"],
                "contextText": "（离线模式）黄霑将五声音阶倒序排列：65321。",
                "bgAudio": "",               // 离线模式下无背景音频
                "expressionMarks": []
            }
            // ... 另外 2 首省略
        ]
    };
}
```

### 步骤 S2：渲染曲目选择卡片

**S2.1** 在 HTML 中预置一个空的曲目列表容器：

```html
<!-- 在 index.html 中预先放置此容器 -->
<div id="track-list" class="track-grid"></div>
```

**S2.2** 在 JavaScript 中获取此容器，然后遍历 `narrativeData.tracks` 数组，为每首曲目创建一个卡片 DOM 元素：

```javascript
function renderTrackCards() {
    // S2.1：获取容器 DOM 元素
    let container = document.getElementById('track-list');
    // S2.2：清空容器中可能存在的旧卡片（防止重复渲染）
    container.innerHTML = '';

    // S2.3：遍历叙事数据中的每一首曲目
    for (let i = 0; i < narrativeData.tracks.length; i++) {
        let track = narrativeData.tracks[i];  // 当前曲目对象
        
        // S2.3.1：创建最外层的卡片 div
        let card = document.createElement('div');
        card.className = 'track-card';         // 设置 CSS 类名（样式由 CSS 文件控制）
        card.setAttribute('data-track-id', track.id);  // 将曲目 ID 存入 DOM 属性，供后续点击事件读取
        
        // S2.3.2：创建曲目标题元素
        let titleEl = document.createElement('h3');
        titleEl.textContent = track.title;     // 只设置纯文本，防止 XSS
        card.appendChild(titleEl);             // 将标题插入卡片内
        
        // S2.3.3：创建难度标签元素
        let levelEl = document.createElement('span');
        levelEl.className = 'level-badge level-' + track.level;  // 根据难度级别设置不同颜色
        levelEl.textContent = '难度：' + track.level;
        card.appendChild(levelEl);
        
        // S2.3.4：创建叙事标签元素（遍历 tags 数组，每个标签渲染为一个彩色小方块）
        let tagsContainer = document.createElement('div');
        tagsContainer.className = 'tags';
        for (let j = 0; j < track.tags.length; j++) {
            let tag = document.createElement('span');
            tag.className = 'tag';
            tag.textContent = track.tags[j];
            tagsContainer.appendChild(tag);
        }
        card.appendChild(tagsContainer);
        
        // S2.3.5：绑定点击事件——点击卡片触发叙事情境呈现
        card.addEventListener('click', function() {
            let trackId = this.getAttribute('data-track-id');  // 从 DOM 属性中读取曲目 ID
            narrateTrack(trackId);  // 调用叙事情境呈现函数（见步骤 S3）
        });
        
        // S2.3.6：将组装完成的卡片追加到容器中
        container.appendChild(card);
    }
}
```

**S2.4** 解释 `createElement` + `appendChild` 的工作机制：`document.createElement('div')` 在浏览器的内存中创建一个尚未挂载到页面 DOM 树的"游离"节点。`container.appendChild(card)` 将该节点插入到 #track-list 容器的子节点列表末尾。浏览器检测到 DOM 树的变更后，自动触发"重排"（reflow）和"重绘"（repaint），用户即可在屏幕上看到新卡片。

### 步骤 S3：响应卡片点击——呈现叙事情境

**当用户点击一张曲目卡片时**，浏览器触发 `narrateTrack(trackId)` 函数。以下是该函数的完整执行流程：

```javascript
async function narrateTrack(trackId) {
    // S3.1：根据 trackId 在 narrativeData.tracks 数组中查找匹配的曲目对象
    let track = narrativeData.tracks.find(function(t) {
        return t.id === trackId;
    });
    
    // S3.2 分支：如果未找到匹配的曲目（用户传入了一个不存在的 ID）
    if (!track) {
        alert('曲目数据未找到，请刷新页面重试。');
        return;  // 终止函数执行，不做任何渲染
    }
    
    // S3.3：创建叙事蒙层（一个覆盖全屏的半透明遮罩）
    let overlay = document.createElement('div');
    overlay.className = 'narrative-overlay';
    overlay.id = 'narrative-overlay';
    
    // S3.4：组装叙事蒙层的 HTML 内容
    let html = '';
    
    // S3.4.1：添加带曲目标题的闭合按钮
    html += '<div class="overlay-header">';
    html += '<h2>' + escapeHTML(track.title) + '</h2>';
    html += '<button id="btn-close-narrative" class="btn-close">&times; 关闭</button>';
    html += '</div>';
    
    // S3.4.2：添加情境文本区域
    html += '<div class="context-text">';
    html += '<p>' + escapeHTML(track.contextText) + '</p>';
    html += '</div>';
    
    // S3.4.3：添加叙事标签显示
    html += '<div class="narrative-tags">';
    for (let i = 0; i < track.tags.length; i++) {
        html += '<span class="narrative-tag">' + escapeHTML(track.tags[i]) + '</span>';
    }
    html += '</div>';
    
    // S3.4.4：添加演奏表情标记区域（仅当 track.expressionMarks 数组非空时）
    if (track.expressionMarks && track.expressionMarks.length > 0) {
        html += '<div class="expression-marks">';
        html += '<h4>演奏表情指引</h4>';
        for (let i = 0; i < track.expressionMarks.length; i++) {
            let mark = track.expressionMarks[i];
            html += '<div class="mark-item">';
            html += '<span class="mark-passage">[' + escapeHTML(mark.passage) + ']</span>';
            html += '<span class="mark-desc">' + escapeHTML(mark.mark) + '</span>';
            html += '</div>';
        }
        html += '</div>';
    }
    
    // S3.5：将组装好的 HTML 注入叙事蒙层
    overlay.innerHTML = html;
    
    // S3.6：将叙事蒙层插入到页面的 <body> 元素末尾
    document.body.appendChild(overlay);
    
    // S3.7：绑定关闭按钮的点击事件
    document.getElementById('btn-close-narrative').addEventListener('click', closeNarrative);
    
    // S3.8：播放背景音频（如果曲目配置了背景音频 URL）
    if (track.bgAudio && track.bgAudio.trim() !== '') {
        await playBackgroundAudio(track.bgAudio);
    }
}
```

**S3.9** 安全性说明——`escapeHTML` 函数的必要性：

```javascript
// 将用户可能输入的 HTML 特殊字符转义，防止跨站脚本攻击（XSS）
function escapeHTML(str) {
    let div = document.createElement('div');
    div.textContent = str;  // textContent 会自动转义 < > & " ' 等字符
    return div.innerHTML;
}
```

**S3.10** 背景音频播放子函数 `playBackgroundAudio` 的完整实现：

```javascript
async function playBackgroundAudio(audioURL) {
    // S3.10.1：创建 HTMLAudioElement 对象
    let audio = new Audio(audioURL);
    audio.id = 'bg-audio-player';  // 赋予 ID，方便后续关闭时停止
    
    // S3.10.2：设置音频参数
    audio.loop = false;    // 不循环播放——叙事背景音频只播放一次
    audio.volume = 0.4;    // 将音量设置为 40%（避免盖过用户思考）
    
    // S3.10.3：尝试播放
    try {
        await audio.play();
    } catch (playError) {
        // S3.10.3.1 分支：浏览器因"自动播放策略"禁止了音频播放
        // 大多数浏览器要求用户先与页面交互（点击）后才能播放音频
        if (playError.name === 'NotAllowedError') {
            // 在叙事蒙层中显示提示文字
            let hint = document.createElement('p');
            hint.className = 'audio-hint';
            hint.textContent = '点击任意位置开始播放背景故事音频';
            hint.style.cursor = 'pointer';
            hint.addEventListener('click', async function() {
                await audio.play();  // 用户交互后再播放
                hint.remove();       // 移除提示文字
            });
            document.getElementById('narrative-overlay').appendChild(hint);
        } else {
            // S3.10.3.2 分支：其他类型的播放错误（如音频文件损坏、格式不支持）
            console.warn('背景音频播放失败：' + playError.message);
        }
    }
    
    // S3.10.4：监听音频播放结束事件——自动关闭叙事蒙层
    audio.addEventListener('ended', function() {
        closeNarrative();  // 调用关闭函数（见步骤 S4）
    });
}
```

### 步骤 S4：关闭叙事蒙层——进入演奏准备状态

```javascript
function closeNarrative() {
    // S4.1：停止背景音频播放（如果存在）
    let audio = document.getElementById('bg-audio-player');
    if (audio) {
        audio.pause();           // 暂停播放
        audio.currentTime = 0;   // 将播放进度重置到开头
        audio.src = '';          // 清空音频源 URL，释放浏览器内存
    }
    
    // S4.2：从 DOM 树中移除叙事蒙层元素
    let overlay = document.getElementById('narrative-overlay');
    if (overlay) {
        overlay.remove();  // remove() 方法将该节点及其所有子节点从 DOM 树中彻底删除
    }
    
    // S4.3：触发自定义事件 'narrative:complete'，通知框模块可以开始工作
    //       后续模块通过监听此事件来获知"叙模块已完成，学习者已准备好演奏"
    let event = new CustomEvent('narrative:complete', {
        detail: {
            trackId: currentTrackId,  // 携带当前曲目 ID，供框模块查找对应的参考标准值
            timestamp: Date.now()     // 记录事件触发时间，用于学习时长统计
        }
    });
    document.dispatchEvent(event);
}
```

### 步骤 S5：叙事表情标记在乐谱上的叠加显示（可选扩展）

**S5.1** 当学习者在框模块中开始演奏时，叙事表情标记不仅仅出现在叙事蒙层中——它们还会被叠加显示在乐谱/指法谱的对应段落旁边。

# 第二模块：装配框架诊断模块（框模块）

## 模块定位

框模块是系统的量化诊断引擎。它的工作是将学习者的演奏音频从"一段声音"转换为"五维精准偏差数据"，并以雷达图形式输出。其技术本质是在浏览器中构建一条**实时音频信号处理管线（Audio Pipeline）**。

## 零件清单（本模块专用）

| 编号 | 零件 | 类型 | 说明 |
|------|------|------|------|
| F-01 | audioCtx | AudioContext | Web Audio API 的核心上下文对象，所有音频节点的"工厂" |
| F-02 | stream | MediaStream | 麦克风采集的原始音频流 |
| F-03 | sourceNode | MediaStreamSourceNode | 将 MediaStream 接入 AudioContext 的节点 |
| F-04 | analyserNode | AnalyserNode | 频谱分析器——本模块的核心处理节点 |
| F-05 | freqData | Uint8Array | 存储频率幅度谱数据的缓冲区（长度 = fftSize/2） |
| F-06 | refValues | JavaScript 对象 | 从 reference_values.json 加载的五维参考标准值 |
| F-07 | radarCanvas | HTMLCanvasElement | 用于绘制雷达图的 Canvas |

## 装配步骤

### 步骤 F1：构建音频信号处理管线

**F1.1** 在浏览器中搭建以下节点链：

```
[麦克风硬件] → getUserMedia() → MediaStream → MediaStreamSourceNode → AnalyserNode → (读取频域数据)
                                                                        ↓
                                                                   Canvas 绘制雷达图
```

**F1.2** 完整代码实现：

```javascript
// ---- 声明全局变量 ----
let audioCtx = null;           // AudioContext 实例
let stream = null;             // 麦克风采集的原始音频流
let sourceNode = null;         // 音源节点
let analyserNode = null;       // 频谱分析节点
let SAMPLE_RATE = 44100;       // 采样率（将在 AudioContext 创建后更新为实际值）
let isRecording = false;       // 录音状态标志位

async function initAudioPipeline() {
    // F1.2.1：创建 AudioContext 对象
    //         注意：Safari 浏览器使用 'webkitAudioContext' 前缀
    let AudioCtxClass = window.AudioContext || window.webkitAudioContext;
    audioCtx = new AudioCtxClass();
    
    // F1.2.2：更新全局采样率为实际值（设备可能是 44100 或 48000）
    SAMPLE_RATE = audioCtx.sampleRate;
    console.log('AudioContext 初始化完成，采样率 = ' + SAMPLE_RATE + ' Hz');
    
    // F1.2.3：请求麦克风权限，获取音频流
    try {
        stream = await navigator.mediaDevices.getUserMedia({
            audio: {
                sampleRate: { ideal: 44100 },   // 请求 44100Hz 采样率（如果设备支持）
                channelCount: { ideal: 1 },     // 请求单声道（笛箫为单音源，无需立体声）
                echoCancellation: false,        // 关闭回声消除（防止误删演奏音频）
                noiseSuppression: false,        // 关闭降噪（保留演奏的全部音频特征）
                autoGainControl: false          // 关闭自动增益（保持原始音量用于气息诊断）
            }
        });
    } catch (err) {
        // F1.2.3.1 分支：用户拒绝了麦克风权限
        if (err.name === 'NotAllowedError' || err.name === 'PermissionDeniedError') {
            alert('请允许浏览器访问麦克风。\n\n'
                + 'Chrome: 点击地址栏左侧的锁图标 → 麦克风 → 允许\n'
                + 'Safari: 设置 → Safari → 麦克风 → 允许');
            return false;  // 返回 false 表示初始化失败
        }
        // F1.2.3.2 分支：设备没有麦克风
        if (err.name === 'NotFoundError') {
            alert('未检测到麦克风设备，请连接外接麦克风后重试。');
            return false;
        }
        throw err;  // 其他未知错误，向上抛出
    }
    
    // F1.2.4：将 MediaStream 接入 AudioContext
    sourceNode = audioCtx.createMediaStreamSource(stream);
    
    // F1.2.5：创建 AnalyserNode（频谱分析器）
    analyserNode = audioCtx.createAnalyser();
    
    // F1.2.6：配置 AnalyserNode 的参数
    analyserNode.fftSize = 2048;
    // 解释：fftSize = 2048 = 2^11，频率分辨率为 SAMPLE_RATE / fftSize = 44100 / 2048 ≈ 21.5 Hz/bin
    //       AnalyserNode.frequencyBinCount = fftSize / 2 = 1024 个频域 bin
    //       有效频率范围为 0 到 SAMPLE_RATE/2 = 0 到 22050 Hz（奈奎斯特频率）
    //       笛箫音域：竹笛 D4(294Hz) - C7(2093Hz)，洞箫 C4(262Hz) - G6(1568Hz)
    //       均落在 AnalyserNode 的可分析范围内
    
    analyserNode.smoothingTimeConstant = 0;
    // 解释：设为 0 表示不做时间平滑——保留每帧的原始频率数据，
    //       不做帧间平均。这对于检测音准的瞬时偏差至关重要。
    //       如果设为 0.8（默认值），会影响音高检测的实时性。
    
    // F1.2.7：连接节点——只连接 source → analyser，不连接到 destination
    //        因为本系统只做分析不需要播放（播放会引入啸叫）
    sourceNode.connect(analyserNode);
    // 注意：analyserNode 不需要也不能连接到 audioCtx.destination！
    //       如果连接了，你的演奏声音会从扬声器播放出来，造成刺耳的反馈啸叫。
    
    isRecording = true;
    return true;  // 返回 true 表示初始化成功
}
```

**F1.3** 检查清单——确保管线正确连接：

| 检查项 | 验证方法 |
|--------|---------|
| audioCtx 状态 | 在控制台输入 `audioCtx.state`，期望值 `'running'`——如果不是，调用 `audioCtx.resume()` |
| stream 状态 | 在控制台输入 `stream.active`，期望值 `true` |
| analyserNode 连接 | 在控制台输入 `analyserNode.context.sampleRate`，应返回数值（如 44100） |

### 步骤 F2：执行自相关函数（ACF）音高检测

**F2.1** 自相关函数（ACF）的数学定义：

给定离散信号序列 `x[n]`（n = 0, 1, 2, ..., N-1），其自相关函数 `R[k]` 定义为：

```
          N-k-1
R[k] =     Σ    x[n] · x[n+k]
           n=0
```

其中 k 为滞后期（lag），k = 8, 9, ..., 512（跳过 k < 8 以避免直流分量和低频噪声干扰）。

**F2.2** 物理含义：`R[k]` 衡量的是信号与其自身延迟 `k` 个样本后的相似程度。如果信号具有周期为 T 的周期性，那么 `R[T]` 将出现一个显著的峰值。基频 f₀ = SAMPLE_RATE / k_peak。

**F2.3** 完整代码实现：

```javascript
function detectPitch() {
    // F2.3.1：获取当前帧的频域幅度数据
    let bufferLength = analyserNode.frequencyBinCount;  // = fftSize/2 = 1024
    let freqData = new Uint8Array(bufferLength);
    // getByteFrequencyData 将当前频域幅度值写入 freqData 数组（0-255 的 8-bit 整数）
    analyserNode.getByteFrequencyData(freqData);
    
    // F2.3.2：将 Uint8Array（0-255）转换为 Float32Array（0.0-1.0）
    let magnitudes = new Float32Array(bufferLength);
    for (let i = 0; i < bufferLength; i++) {
        magnitudes[i] = freqData[i] / 255.0;
    }
    // 解释：除以 255 将数据归一化到 [0, 1] 区间，这是后续自相关计算的必要预处理
    
    // F2.3.3：对归一化后的频率幅度谱执行自相关计算
    let maxLag = Math.min(512, bufferLength);  // 最大滞后期（bin 数），不超过 512
    let autocorrelation = new Float32Array(maxLag);
    
    for (let lag = 8; lag < maxLag; lag++) {
        // F2.3.3.1：从 lag=8 开始（跳过 k=0 的直流分量，以及低频噪声区域的 k=1..7）
        let sum = 0.0;
        for (let n = 0; n < bufferLength - lag; n++) {
            sum += magnitudes[n] * magnitudes[n + lag];
        }
        autocorrelation[lag] = sum;
    }
    
    // F2.3.4：在自相关数组中找峰值（最大值）的位置
    let peakLag = 8;       // 峰值对应的滞后期
    let peakValue = autocorrelation[8];  // 峰值幅度
    for (let lag = 9; lag < maxLag; lag++) {
        if (autocorrelation[lag] > peakValue) {
            peakValue = autocorrelation[lag];
            peakLag = lag;
        }
    }
    
    // F2.3.5：峰值滞后期转换为频率——这是频谱的自相关，每个 bin 代表一个频率分量
    //         频率 = peakLag * (SAMPLE_RATE / fftSize) = peakLag * 频域分辨率
    let freqResolution = SAMPLE_RATE / analyserNode.fftSize;
    // 例如：44100 / 2048 ≈ 21.53 Hz/bin
    let detectedFreq = peakLag * freqResolution;
    // 例如：如果 peakLag = 20，detectedFreq = 20 * 21.53 ≈ 430.6 Hz
    //       这个频率接近 A4 La 的标准频率 440 Hz
    
    // F2.3.6：频率 → MIDI 音符号（用于精确计算音准偏差）
    let midiNote;
    if (detectedFreq > 0) {
        // MIDI 音符号公式：note = 69 + 12 * log2(f / 440)
        // 解释：A4 (La) = MIDI 69 = 440 Hz，半音间隔 = 2^(1/12)
        midiNote = 69 + 12 * Math.log2(detectedFreq / 440.0);
    } else {
        midiNote = 0;  // 无声或检测失败
    }
    
    // F2.3.7：返回检测结果
    return {
        detectedFreq: detectedFreq,      // 检测到的实际频率 (Hz)
        midiNote: midiNote,              // MIDI 音符号（浮点数，如 69.2 ≈ A4 略高）
        cents: null,                     // 音分偏差——将在 F3 步骤中与参考音高对比后填入
        peakLag: peakLag,                // 峰值滞后期（诊断用）
        confidence: peakValue            // 检测置信度（峰值越高 = F0 越清晰 = 越可靠）
    };
}
```

**F2.4** 数值代入演算示例：

- 假设学习者吹奏 A4 La 音，实际上吹出的是 443 Hz（略偏高）
- SAMPLE_RATE = 44100，fftSize = 2048 → 频域分辨率 = 21.53 Hz/bin
- peakLag = 443 / 21.53 ≈ 20.6，四舍五入为 21（整数 bin 索引）
- detectedFreq = 21 * 21.53 ≈ 452.1 Hz（有量化误差）
- midiNote = 69 + 12 * log2(452.1 / 440) ≈ 69 + 12 * 0.0398 ≈ 69.48
- 四舍五入到最近半音 → 69（A4）→ 音分偏差 = 1200 * log2(452.1 / 440) ≈ +46.8 音分
- **结论**：该学习者的 A4 音偏高约 47 音分（接近四分之一半音偏高）

> 注意：频率分辨率为 21.53 Hz/bin 时，bin 级别的量化误差约为 ±10.8 Hz。对于 440 Hz 的 A4 音，这相当于 ±42 音分的理论检测误差上限。在实施例 3 中通过时域 ACF（而非频域 bin 索引）进一步细化检测精度。

**F3.3** 五维偏差计算函数：

```javascript
function computeFiveDimensionalDiagnosis(pitchResult, rhythmMs, breathDbs, 
                                          transitionMs, timbreCentroid, ref) {
    // F3.3.1：音准偏差（音分）
    let centsDeviation = 1200 * Math.log2(pitchResult.detectedFreq / ref.pitch_ref);
    // 示例：detectedFreq=443, ref=440 → centsDeviation=1200*log2(1.0068)≈+11.7
    
    // F3.3.2：节奏偏差（毫秒）
    let rhythmDeviation = rhythmMs;  // 由节拍检测模块提供（本节略）
    
    // F3.3.3：气息平稳度（dB 标准差）
    // breathDbs 是连续N个音符的气息强度数组 [dB1, dB2, ..., dBn]
    let mean = breathDbs.reduce((a,b) => a+b) / breathDbs.length;  // 均值
    let variance = breathDbs.reduce((a,b) => a + (b-mean)*(b-mean), 0) / breathDbs.length;
    let stability = Math.sqrt(variance);  // 标准差
    
    // F3.3.4：指法过渡时间（毫秒）
    let fingeringDeviation = transitionMs;  // 由指法检测模块提供（本节略）
    
    // F3.3.5：音色偏离度（频谱质心差异，无量纲）
    let timbreDeviation = Math.abs(timbreCentroid - ref.timbre_centroid_ref) 
                          / ref.timbre_centroid_ref;
    
    // F3.3.6：组装诊断报告
    return {
        dimensions: [
            { name: '音准',   value: centsDeviation,  unit: '音分', 
              ref: 0,         threshold: ref.pitch_tolerance_cents, 
              grade: absGrade(centsDeviation, ref.pitch_tolerance_cents) },
            { name: '节奏',   value: rhythmDeviation, unit: 'ms',   
              ref: 0,         threshold: ref.rhythm_tolerance_ms,   
              grade: absGrade(rhythmDeviation, ref.rhythm_tolerance_ms) },
            { name: '气息',   value: stability,        unit: 'dB σ', 
              ref: 0,         threshold: ref.breath_stability_threshold, 
              grade: absGrade(stability, ref.breath_stability_threshold) },
            { name: '指法',   value: fingeringDeviation, unit: 'ms', 
              ref: 0,         threshold: ref.fingering_transition_max_ms, 
              grade: absGrade(fingeringDeviation, ref.fingering_transition_max_ms) },
            { name: '音色',   value: timbreDeviation,   unit: '%',    
              ref: 0,         threshold: 0.15,          
              grade: absGrade(timbreDeviation, 0.15) }
        ],
        overallGrade: null  // 将在 F4 步骤中计算综合等级
    };
}

// 辅助函数：根据偏差绝对值与阈值的比值判定等级
function absGrade(value, threshold) {
    let ratio = Math.abs(value) / threshold;
    if (ratio <= 1.0) return '优';       // 偏差在阈值内
    if (ratio <= 2.0) return '良';       // 偏差不超过阈值的2倍
    if (ratio <= 3.0) return '待改进';    // 偏差较大
    return '需重点练习';                   // 严重偏差
}
```

**F4.2** 雷达图绘制伪代码（五轴，每轴对应一个诊断维度）：

```javascript
function drawRadarChart(diagnosisReport) {
    let canvas = document.getElementById('radar-canvas');
    let ctx = canvas.getContext('2d');
    let w = canvas.width;    // 400
    let h = canvas.height;   // 400
    let cx = w / 2;          // 中心 x = 200
    let cy = h / 2;          // 中心 y = 200
    let radius = 150;        // 雷达图半径
    let dims = diagnosisReport.dimensions;  // 5个维度
    
    // F4.2.1：清空画布
    ctx.clearRect(0, 0, w, h);
    
    // F4.2.2：绘制背景网格（3层同心五边形 + 从中心发出的5条放射线）
    for (let level = 1; level <= 3; level++) {
        ctx.beginPath();
        for (let i = 0; i < 5; i++) {
            let angle = (2 * Math.PI * i / 5) - Math.PI / 2;  // 从正上方开始
            let r = radius * (level / 3);  // level=1→50px, 2→100px, 3→150px
            let x = cx + r * Math.cos(angle);
            let y = cy + r * Math.sin(angle);
            if (i === 0) ctx.moveTo(x, y); else ctx.lineTo(x, y);
        }
        ctx.closePath();
        ctx.strokeStyle = '#ddd';
        ctx.stroke();
    }
    
    // F4.2.3：绘制5条放射线（从中心到外圈顶点）
    for (let i = 0; i < 5; i++) {
        let angle = (2 * Math.PI * i / 5) - Math.PI / 2;
        ctx.beginPath();
        ctx.moveTo(cx, cy);
        ctx.lineTo(cx + radius * Math.cos(angle), cy + radius * Math.sin(angle));
        ctx.strokeStyle = '#eee';
        ctx.stroke();
        
        // F4.2.4：在每条放射线的末端标注维度名称
        let labelX = cx + (radius + 25) * Math.cos(angle);
        let labelY = cy + (radius + 25) * Math.sin(angle);
        ctx.fillStyle = '#333';
        ctx.font = '14px Microsoft YaHei';
        ctx.textAlign = 'center';
        ctx.textBaseline = 'middle';
        ctx.fillText(dims[i].name, labelX, labelY);
    }
    
    // F4.2.5：绘制学习者的实际数据多边形（蓝色填充）
    ctx.beginPath();
    for (let i = 0; i < 5; i++) {
        let angle = (2 * Math.PI * i / 5) - Math.PI / 2;
        // 将偏差值映射到半径长度：偏差越小 → 半径越大（表示越好）
        // 映射公式：r = max(0, radius * (1 - |value|/threshold/3))
        //          偏差=0时r=radius，偏差=3倍阈值时r=0
        let normalizedValue = Math.max(0, 1 - Math.abs(dims[i].value) / (dims[i].threshold * 3));
        let r = radius * normalizedValue;
        let x = cx + r * Math.cos(angle);
        let y = cy + r * Math.sin(angle);
        if (i === 0) ctx.moveTo(x, y); else ctx.lineTo(x, y);
    }
    ctx.closePath();
    ctx.fillStyle = 'rgba(41, 128, 185, 0.3)';  // 半透明蓝色填充
    ctx.fill();
    ctx.strokeStyle = '#2980b9';                   // 深蓝色描边
    ctx.lineWidth = 2;
    ctx.stroke();
    
    // F4.2.6：在每个数据顶点绘制圆点标记
    for (let i = 0; i < 5; i++) {
        let angle = (2 * Math.PI * i / 5) - Math.PI / 2;
        let normalizedValue = Math.max(0, 1 - Math.abs(dims[i].value) / (dims[i].threshold * 3));
        let r = radius * normalizedValue;
        let x = cx + r * Math.cos(angle);
        let y = cy + r * Math.sin(angle);
        ctx.beginPath();
        ctx.arc(x, y, 5, 0, 2 * Math.PI);  // 半径5px的圆点
        ctx.fillStyle = '#2980b9';
        ctx.fill();
        
        // F4.2.7：在每个圆点旁标注实际偏差值
        ctx.fillStyle = '#555';
        ctx.font = '11px Microsoft YaHei';
        ctx.fillText(dims[i].value.toFixed(1) + dims[i].unit, x + 8, y - 8);
    }
    
    // F4.2.8：在雷达图下方生成修复建议文本
    generateRepairSuggestions(diagnosisReport);
}
```
