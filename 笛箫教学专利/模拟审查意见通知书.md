# 模拟国家知识产权局审查意见通知书

**申请号**：模拟审查 — 基于叙·框·境·创四维框架的笛箫民乐交互式教学系统及方法  
**审查部门**：光电技术发明审查部  
**审查员**：模拟审查员（Agent-Examiner）  
**审查日期**：2026-07-07  

---

## 第一部分：总体评价与发明点结论

### 一、发明点确认

经审查，本发明相对于现有技术存在以下**可被认可的发明点**：

**发明点 1**：针对笛箫等吹管乐器无固定键位的特点，在交互式教学系统中采用自相关函数（ACF）音高检测替代键位匹配检测，并结合五维技术错配诊断矩阵（音准/节奏/气息/指法/音色）输出雷达图诊断报告——解决了现有智能教学系统无法适配吹管乐器的问题。

**发明点 2**：将可参数化调节的模拟演出环境（噪音强度 40-70dB、合奏延迟 0-200ms、触觉振动 2-15Hz）首次纳入教学系统的技术方案，使学习者可在安全环境中经历可量化的演出压力训练。

**发明点 3**：通过梅尔频率倒谱系数（MFCC）特征提取→主成分分析（PCA）降维→余弦相似度匹配→三联创造性评分（风格契合度×0.4+风格辨识度×0.3+即兴复杂度×0.3），首次将吹管乐器即兴演奏评估从主观审美判断转化为可量化的计算链。

**结论：本发明具有发明点，具备授予专利权的可能性。但需根据以下审查意见进行修改后方可进入后续程序。**

## 第二部分：说明书审查意见

### 审查意见 1（形式缺陷）：背景技术缺少对比文献的具体引用

**问题描述**：背景技术中仅笼统提及"目前已有的智能音乐教学系统，包括基于键位匹配的钢琴教学系统和基于多弦识别的吉他教学系统"，但未给出任何对比文献的专利号、公开号或具体产品名称及版本。审查员无法在检索报告中核对这些对比文献是否为真实的现有技术。

**修改要求**：需在背景技术中引用至少 2-3 篇已公开的专利文献或学术文献，明确标注公开号/出版信息，并说明本发明与这些文献的技术区别。例如：
- 某钢琴教学评分系统的中国专利公开号
- Yousician 或 Simply Piano 的相关技术公开信息
- 某智能乐器教学系统的学术论文

**法律依据**：《专利法实施细则》第 17 条——说明书应当对发明作出清楚、完整的说明，以所属技术领域的技术人员能够实现为准。

---

### 审查意见 2（实质缺陷）：权利要求 11 在说明书中缺乏充分支持

**问题描述**：权利要求 11 限定"还包括云端AI助教模块，所述云端AI助教模块基于浏览器端采集的学习进度数据，生成针对单个学习者的个性化练习建议文本"。然而，说明书中仅在模块间通信协议（第（五）节）末尾一句提到"生成当前学习会话的完整学习报告，并将学习进度数据持久化存储于学习终端的本地存储中"，并未对"云端AI助教模块"的结构、算法或工作原理作出任何描述。

**修改要求**：方案一——在说明书"技术方案"或新增的"具体实施方式"中，补写云端AI助教模块的技术方案，说明该模块如何基于学习进度数据生成个性化建议（至少包括数据输入→处理算法→输出的完整技术链路）。方案二——删除权利要求 11。

**法律依据**：《专利法》第 26 条第 4 款——权利要求书应当以说明书为依据，清楚、简要地限定要求专利保护的范围。

---

### 审查意见 3（实质缺陷）：创造评估模块的技术效果缺乏实验数据验证

**问题描述**：说明书中对创造评估模块的技术效果使用了大量定性描述（如"将即兴演奏评估从主观审美判断转化为可量化的…评分体系"），但未提供任何实验数据来证明"三联创造性评分"与人类专家评分之间的相关性（例如皮尔逊相关系数）或评估准确率。

**修改要求**：建议在具体实施方式中增加一段实验验证数据，例如：收集 N 名笛箫学习者的即兴演奏录音，分别由人类专家打分和本发明系统打分，计算两者的相关性系数，以此作为创造性评分的有效性证据。若暂无实验数据，至少应提供"所述三联评分中各因子的权重（0.4:0.3:0.3）的确定依据"——是来自统计分析还是专家经验。

**法律依据**：《专利法》第 22 条第 4 款——实用性要求。虽然教学系统不涉及工业产品制造，但创造评估模块的有效性直接影响系统的实用性论证。

---

### 审查意见 4（形式缺陷）：有益效果第 5 条可能构成不当表述

**问题描述**：有益效果第 5 条表述为"零依赖部署。系统以纯静态网页文件形式实现，无需后端服务、数据库或客户端软件安装，一个现代浏览器即可运行全部功能。"其中"零依赖""一个现代浏览器即可运行全部功能"等表述可能引起审查员的如下质疑：（1）现代浏览器本身即为依赖；（2）若系统声称无需任何客户端软件，但麦克风驱动、蓝牙驱动等仍需操作系统支持。

**修改要求**：建议将"零依赖"修改为"轻量部署"或"低环境依赖"，并限缩为"无需安装专用的教学客户端软件、无需配置后端服务器和数据库管理系统"。

---

### 审查意见 5（形式缺陷）：表 3 中部分参数值的表述不够清楚

**问题描述**：表 3（场景参数配置）中，"合奏声部延迟(ms)"在合奏排练模式下填写为"50→0梯度"，"振动频率(Hz)"在合奏排练模式下填写为"10/4(强/弱拍)"。这些表述中"→"和"/"符号在专利申请文件中不规范——审查员无法确定这些符号的确切技术含义。

**修改要求**：将"50→0梯度"改写为完整的文字描述："初始值50ms，每次达标后递减10ms，直至0ms"；将"10/4(强/弱拍)"改写为"强拍振动10Hz，弱拍振动4Hz"。

---

### 审查意见 6（建议）：附图说明中应补充"图 4 为……"中提到的"云端AI助教"

**问题描述**：图 4 的附图说明中提到了"云端AI助教"，但说明书的系统硬件组成（表 1）和技术方案中均未描述这一组件的具体位置和功能——仅在权利要求 11 中出现。若该组件确为系统组成部分，需在说明书正文中补充描述；若否，应删除附图说明中的相关表述。

**修改要求**：与审查意见 2 联动处理。

## 第三部分：权利要求书审查意见

### 审查意见 7（实质缺陷）：独立权利要求 1 保护范围可能过窄

**问题描述**：独立权利要求 1 四个模块的功能描述中，存在多处与"浏览器"特定实现的绑定（如"叙事情境模块在演奏前向学习者呈现"——隐含了 UI 界面）。若审查员检索到一篇"离线硬件设备"中采用类似四模块架构的教学系统，但该设备无 UI 界面而是通过硬件指示灯和蜂鸣器反馈——则本权利要求将无法覆盖该变体。

**修改建议（非强制）**：考虑在独立权利要求 1 中使用更上位的功能性描述，例如将"呈现"替换为"输出"，将"界面"替换为"交互接口"，将浏览器特定实现下放到从属权利要求中。

---

### 审查意见 8（实质缺陷）：权利要求 3 和权利要求 6 限定了具体浏览器 API，保护范围过窄

**问题描述**：权利要求 3 限定了"浏览器 Web Audio API 的 MediaStream 接口，通过 navigator.mediaDevices.getUserMedia({audio: true})方法获取"。权利要求 6 限定了"浏览器 OscillatorNode 节点"。这两个权利要求将保护范围限缩到了浏览器 JavaScript 环境下的特定 API 调用。若侵权者使用 C++ 编写的本地应用、或使用 Android/iOS 原生音频 API、或使用 Node.js 服务端处理音频，均不落入权利要求 3 和 6 的字面范围。

**修改要求**：将权利要求 3 中的具体 API 改写为功能性限定，例如"所述音频采集单元通过操作系统提供的音频采集应用程序接口获取设备麦克风输入的实时音频流"。将权利要求 6 中的"浏览器 OscillatorNode 节点"改写为"数字音频信号生成模块"或"软件粉红噪声生成器"。具体的浏览器 API 细节可保留在说明书的实施例中，但不应写入权利要求。

**法律依据**：《专利法》第 26 条第 4 款——权利要求书应当清楚、简要。过于具体的实现细节使得权利要求不清楚（与发明要解决的技术问题的抽象层次不匹配）。

---

### 审查意见 9（实质缺陷）：权利要求 12 可能不具备创造性

**问题描述**：权利要求 12 限定"所述笛箫民乐交互式教学系统经过数据文件替换后，同样适用于尺八和葫芦丝吹管乐器"。其中"数据文件替换"是指将技术参考标准值文件、风格模板库文件和叙事曲目库文件替换为另一乐器的对应文件。这一技术特征本质上属于"根据不同乐器预先设置不同的参数集合"——这在智能乐器教学系统中属于本领域的常规技术手段（例如现有钢琴教学系统允许在"古典模式"和"流行模式"之间切换，即替换评分标准文件）。将笛箫的参数文件替换为尺八的参数文件，属于本领域技术人员在面临"将系统适配到另一吹管乐器"这一技术问题时无需创造性劳动就能想到的方案。

**修改建议**：若希望保留跨乐器迁移这一保护点，建议在权利要求 12 中增加"技术效果"限定——例如"……在替换数据文件后，无需修改所述系统的核心程序代码即可实现对尺八和葫芦丝的适配"——并将"无需修改核心程序代码"作为技术特征写入，而非仅"替换数据文件"。

**法律依据**：《专利法》第 22 条第 3 款——创造性。

---

### 审查意见 10（形式缺陷）：权利要求 13（方法独立权利要求）存在步骤划分与系统权利要求不对应的问题

**问题描述**：方法权利要求 13 的四个步骤与系统权利要求 1 的四个模块在逻辑上对应，但步骤描述中缺少对"中间数据流向"的限定。例如，S2（框架诊断步骤）中"输出可视化诊断报告"后的诊断数据流向未在方法权利要求中体现——而系统权利要求中通过"事件总线"明确了模块间的通信关系。这使得方法权利要求 13 可能被解释为"四个独立步骤的简单串行排列"，而非有数据依赖关系的完整流程。

**修改要求**：在方法权利要求的 S2 和 S3 之间、S3 和 S4 之间增加中间步骤，限定前后步骤之间的数据传递。例如：增加"将所述诊断报告中的偏差等级判定结果作为场景淬炼步骤中场景类型选择的依据"。

## 第五部分：审查结论

### 发明点结论

**本发明具有发明点。** 自相关函数（ACF）音高检测适配吹管乐器 + 五维错配诊断矩阵 + 可参数化演出压力模拟 + MFCC-PCA-余弦三重创造性评分的四模块事件总线闭环架构，在现有技术中未见公开或暗示。

### 授权前景

在完成上述 P0 级修改（特别是权利要求 3/6 去除浏览器 API 绑定、权利要求 12 强化跨乐器迁移的技术特征、权利要求 11 补全说明书支持）后，本发明**具备授予专利权的实质条件**。

### 预计审查周期

若按期提交符合要求的修改文件，预计 2-3 次审查意见通知书后可进入授权程序。
